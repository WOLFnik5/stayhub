# 00 — Свіжий baseline

Модель: GPT-5.6 Luna / low. Передумов немає. Спочатку EXECUTOR.md і STATUS.md.

Завдання — отримати відтворюваний стан, не виправляти бізнесовий код.

1. Перевір робоче дерево, JDK/Maven і доступність Docker, не друкуючи секрети.
2. Запусти один `mvn clean verify`. Зафіксуй точну команду, версії та результат. Якщо прогін перервано, не підсумовуй неповні звіти як повний suite.
3. За помилок прочитай тільки відповідні surefire-звіти. Згрупуй за першопричиною: середовище, компіляція, SQL, assertion, concurrency. Особлива увага PersistenceIntegrationTest, BookingOutboxIntegrationTest, BookingCheckoutIntegrationTest, BookingControllerIntegrationTest.
4. Не відновлюй старий SQL: у BookingRepositoryImpl уже є незакомічені CAST для nullable параметрів. Не оголошуй старі падіння актуальними.
5. Запиши результат у STATUS.md. Якщо тестовий baseline червоний, сформулюй окрему вузьку задачу для Terra medium з конкретним відтворенням. Залежні поведінкові зміни починати після розв'язання baseline; незалежна діагностика 01/02 може виконуватися з явно записаним обмеженням.

Готово: є свіжий повний результат або точний блокер і команда відтворення. PASS лише якщо verify успішний; завершений діагностичний звіт при падінні має FAIL/BLOCKED. Прикладні файли не змінені.
